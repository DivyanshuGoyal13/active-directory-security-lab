# Active Directory Security Lab — Configuration & Implementation

## Overview

This project documents the deployment and security configuration of a Windows Server Active Directory environment and a Windows 11 client machine.

The lab was designed to provide hands-on experience with:

- Windows Server administration
- Active Directory Domain Services (AD DS)
- Domain Controller deployment
- Group Policy configuration
- Password security
- Account lockout policies
- Domain authentication
- Active Directory user management
- Windows security event logging
- Client-to-domain integration

## Environment

### Server

- Operating System: Windows Server
- Role: Domain Controller
- Active Directory Domain Services (AD DS)
- Domain environment configured for centralized authentication and policy management

### Client

- Operating System: Windows 11
- Joined to the Active Directory domain
- Used to verify domain authentication and security policies

## Active Directory Configuration

The Windows Server system was configured as an Active Directory Domain Controller.

The following configuration tasks were completed:

1. Windows Server installation
2. Server initial configuration
3. Active Directory Domain Services role installation
4. Domain Controller promotion
5. Active Directory domain configuration
6. Group Policy updates
7. User authentication testing

## Security Configuration

### Account Lockout Policy

An account lockout policy was configured to help protect against repeated failed authentication attempts.

The policy was tested by intentionally generating failed login attempts and verifying that the account became locked.

### Password Policy

Password policy settings were configured through Group Policy to enforce stronger authentication requirements.

The configuration was tested to confirm that the policy was being applied to domain accounts.

## Authentication Testing

Domain authentication was verified using a domain account.

The `whoami` command was used to confirm that the system was authenticating the user through the Active Directory domain.

## Account Lockout Testing

The account lockout configuration was tested by intentionally entering incorrect credentials.

After the configured threshold was reached, the account became locked.

The account was subsequently located and unlocked through Active Directory Users and Computers.

## Security Event Logging

Windows Event Viewer was used to examine security events generated by the account lockout.

Event ID **4740** was reviewed to identify the account associated with the lockout and demonstrate how Windows security logs can be used for investigation.

## Windows 11 Client

A Windows 11 client machine was deployed and configured as part of the lab environment.

The client was used to demonstrate integration with the Active Directory domain and centralized authentication.
